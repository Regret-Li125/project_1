# 个人知识库 / 笔记助手本地应用 AI 代理可执行项目书（详细版）

## 0. 给 AI 代理的执行说明

你是一名全栈开发代理，需要基于本项目书实现一个可运行的个人知识库 / 笔记助手本地桌面应用 MVP。

执行原则：

- 优先完成可用产品，而不是停留在原型或静态界面。
- 保持功能闭环：创建笔记、编辑笔记、搜索笔记、标签筛选、随机复习必须能真实工作。
- 默认使用本地应用数据存储，不接入登录、云同步或远程后端服务。
- 若当前代码仓库已有技术栈，优先沿用现有技术栈。
- 若是空仓库，推荐使用 Electron + React + Vite + TypeScript 实现本地桌面应用。
- 所有关键功能完成后，需要启动本地应用并完成基础自测。

## 1. 项目目标

构建一个面向个人用户的轻量级本地知识管理应用，支持 Markdown 笔记、标签分类、全文搜索、最近编辑、每日回顾和随机复习。

产品体验方向升级为：

- 像 Obsidian 一样：本地优先、Markdown 文件化、双向链接、反向链接、关系图谱、快速切换、命令面板。
- 像 Get 笔记一样：提供低摩擦的 AI 速记入口，支持文字、语音、图片、链接等内容快速转成结构化笔记。
- 不复制任何竞品品牌、图标、商标、配色或专有界面，只借鉴产品范式和交互思路。

MVP 的目标是让用户可以：

- 快速记录知识。
- 用标签整理知识。
- 用搜索找回知识。
- 通过回顾机制重新发现旧笔记。
- 通过双链和图谱看到知识之间的关系。
- 通过 AI 速记入口把零散信息整理成可复用笔记。

## 4. 推荐技术方案

如果仓库为空，使用以下技术方案：

- 应用形态：本地桌面应用
- 桌面框架：Electron
- 渲染层构建工具：Vite
- 渲染层框架：React
- 语言：TypeScript
- 样式：CSS Modules、普通 CSS 或 Tailwind CSS
- Markdown 渲染：react-markdown
- 搜索：MVP 阶段使用本地字符串匹配，可选 Fuse.js
- 存储：应用数据目录中的 JSON 文件
- 桌面 API 通信：Electron IPC
- 打包工具：electron-builder 或 Electron Forge

推荐优先级：

1. 若需要快速交付，使用 Electron + JSON 文件存储。
2. 若预计笔记较多，后续可迁移到 SQLite。
3. MVP 默认使用 JSON 文件即可，避免引入数据库复杂度。

不采用 Web 打开方式：

- 不要求用户通过浏览器访问页面。
- 不以部署网站作为交付目标。
- 开发阶段可以使用 Vite 服务支撑 Electron 渲染层，但用户体验必须是打开本地应用窗口。

## 7. 数据模型

### 7.1 Note

```ts
type Note = {
  id: string;
  title: string;
  content: string;
  tags: string[];
  createdAt: string;
  updatedAt: string;
  lastOpenedAt: string | null;
  lastReviewedAt: string | null;
};
```

字段说明：

- `id`：唯一 ID。
- `title`：笔记标题，允许为空，但展示时需要回退为“未命名笔记”。
- `content`：Markdown 正文。
- `tags`：标签名称数组。
- `createdAt`：创建时间，ISO 字符串。
- `updatedAt`：最近更新时间，ISO 字符串。
- `lastOpenedAt`：最近打开时间。
- `lastReviewedAt`：最近复习时间。

### 7.2 本地应用数据存储

每个笔记保存为独立的 `.md` 文件，采用 Obsidian 风格的 Vault 目录结构。

默认存储位置：

```text
应用数据目录 / personal-knowledge-notes / vault /
```

Vault 目录结构：

```text
vault/
  .vault-meta.json          # 文件夹元数据（版本号、文件夹列表）
  notes/                    # 根目录笔记（folderId === null）
    笔记标题.md
  folders/                  # 按文件夹 ID 分目录
    <文件夹UUID>/
      笔记标题.md
```

.md 文件格式（YAML frontmatter）：

```yaml
---
id: "uuid"
title: "标题"
tags: ["标签1", "标签2"]
folderId: "文件夹UUID"
sourceType: "manual"
createdAt: "2026-05-01T10:00:00.000Z"
updatedAt: "2026-05-01T10:30:00.000Z"
lastOpenedAt: null
lastReviewedAt: null
---
Markdown 正文内容
```

Electron 存储要求：

- 主进程负责读写 `.md` 文件和 `.vault-meta.json`。
- 渲染进程通过 preload 暴露的安全 API 读写数据。
- 渲染进程不要直接访问 Node.js `fs`。
- 文件路径必须使用 `app.getPath('userData')` 生成，避免写入项目目录。
- 如果 Vault 目录不存在，应用启动时自动创建并返回空笔记列表。
- 文件夹目录使用 UUID 命名，重命名文件夹只更新 `.vault-meta.json`，不移动文件。
- 旧版 `notes.json` 会自动迁移为独立 `.md` 文件，迁移后重命名为 `notes.json.migrated`。

## 8. 核心业务规则

### 8.1 新建笔记

当用户点击“新建笔记”：

1. 创建一个新的 Note。
2. 默认标题为“未命名笔记”。
3. 默认正文为空字符串。
4. 默认标签为空数组。
5. 写入本地数据文件。
6. 自动选中新笔记并进入编辑状态。

### 8.2 自动保存

标题、正文或标签发生变化时：

1. 更新当前 Note。
2. 更新 `updatedAt`。
3. 写入本地数据文件。
4. 展示“已保存”状态。

建议使用 300ms 到 800ms 防抖，避免频繁写入。

### 8.3 删除笔记

当用户点击删除：

1. 弹出确认提示。
2. 用户确认后删除当前 Note。
3. 更新本地数据文件。
4. 返回笔记列表或选中下一篇笔记。

### 8.4 搜索

搜索范围：

- 标题
- 正文
- 标签

匹配规则：

- 不区分大小写。
- 搜索词为空时展示全部笔记。
- 命中任一字段即视为匹配。

### 8.5 标签筛选

当用户选择标签：

1. 只展示包含该标签的笔记。
2. 搜索词和标签筛选可以同时生效。
3. 提供清除筛选入口。

### 8.6 今日回顾

今日回顾展示 3 篇笔记。

选择规则：

1. 优先选择 `lastReviewedAt` 为空的笔记。
2. 其次选择最久未复习的笔记。
3. 若数量不足，使用最近编辑之外的其他笔记补齐。
4. 笔记总数不足 3 篇时展示全部。

当用户从今日回顾打开笔记：

- 更新 `lastReviewedAt` 为当前时间。
- 更新 `lastOpenedAt` 为当前时间。

### 8.7 随机复习

当用户点击“随机复习”：

1. 从全部笔记中随机选择一篇。
2. 打开该笔记。
3. 更新 `lastReviewedAt`。
4. 更新 `lastOpenedAt`。

如果没有笔记：

- 展示空状态，引导用户新建第一篇笔记。

## 17. 需求优先级矩阵

## 18. 用户故事

### 18.1 记录知识

作为一个持续学习的用户，我希望可以快速创建一篇 Markdown 笔记，以便在灵感出现时立即记录。

验收条件：

- 用户在任意主要界面都能看到“新建笔记”入口。
- 新建后不需要额外跳转确认，直接进入编辑区。
- 即使标题为空，笔记也不会丢失。
- 标题为空时，列表中显示“未命名笔记”。

### 18.2 整理知识

作为一个有多主题笔记的用户，我希望可以给笔记添加多个标签，以便一篇笔记能同时属于多个主题。

验收条件：

- 一篇笔记可以添加多个标签。
- 重复标签不能被重复添加。
- 标签首尾空格需要自动去除。
- 删除标签只影响当前笔记，不会删除其他笔记上的同名标签。

### 18.3 找回知识

作为一个已经写了很多笔记的用户，我希望通过关键词搜索标题、正文和标签，以便快速找回旧内容。

验收条件：

- 搜索不区分大小写。
- 搜索中文、英文、数字均可工作。
- 搜索词为空时回到正常列表。
- 搜索和标签筛选可以叠加。

### 18.4 复习知识

作为一个容易遗忘旧笔记的用户，我希望系统每天推荐几篇旧笔记，以便我能重新利用过去记录的内容。

验收条件：

- 今日回顾最多展示 3 篇。
- 优先展示未复习或较久未复习的笔记。
- 从今日回顾打开笔记后，需要更新复习时间。
- 无笔记时展示引导，不展示空白模块。

## 20. 状态设计

```ts
type AppState = {
```

- `selectedNote`
- `filteredNotes`
- `recentNotes`

- `reviewNotes`
- `hasActiveFilter`

建议实现方式：

```ts
const selectedNote = notes.find((note) => note.id === selectedNoteId) ?? null;
const filteredNotes = filterNotes(notes, searchQuery, selectedTag);
const recentNotes = getRecentNotes(notes, 5);
```

## 21. 工具函数规格

### 21.1 `createNote`

用途：创建一篇新笔记。

输入：

```ts
type CreateNoteInput = {
  title?: string;
  content?: string;
  tags?: string[];
};
```

输出：

```ts
Note
```

规则：

- `id` 使用 `crypto.randomUUID()`，如果环境不支持则使用时间戳兜底。
- `createdAt`、`updatedAt` 使用同一个当前时间。
- `lastOpenedAt` 默认为当前时间。
- `lastReviewedAt` 默认为 `null`。

### 21.2 `updateNote`

用途：更新指定笔记。

输入：

```ts
type UpdateNoteInput = {
  id: string;
  patch: Partial<Pick<Note, 'title' | 'content' | 'tags' | 'lastOpenedAt' | 'lastReviewedAt'>>;
};
```

规则：

- 找到对应笔记后合并 patch。
- 当标题、正文或标签变化时更新 `updatedAt`。
- 当只更新 `lastOpenedAt` 或 `lastReviewedAt` 时，可以不更新 `updatedAt`。

### 21.3 `deleteNote`

用途：删除指定笔记。

输入：

```ts
id: string
```

输出：

```ts
Note[]
```

规则：

- 如果 ID 不存在，返回原数组。
- 删除当前选中笔记后，应清空 `selectedNoteId` 或选中下一篇。

### 21.4 `filterNotes`

用途：执行搜索和标签筛选。

输入：

```ts
type FilterNotesInput = {
  notes: Note[];
  searchQuery: string;
  selectedTag: string | null;
};
```

规则：

- 先按标签筛选，再按搜索词筛选。
- 搜索标题、正文和标签。
- 使用 `toLowerCase()` 做英文大小写兼容。
- 中文不需要额外分词。

### 21.5 `getTagStats`

用途：生成标签统计。

输出：

```ts
type TagStat = {
  name: string;
  count: number;
};
```

规则：

- 标签名为空字符串时忽略。
- 按 count 倒序排列。
- count 相同时按名称排序。

### 21.6 `pickReviewNotes`

用途：选择今日回顾笔记。

规则：

- 排除内容和标题都为空的笔记。
- 优先 `lastReviewedAt === null`。
- 其次按 `lastReviewedAt` 从旧到新排序。
- 最多返回 3 篇。
- 如果笔记数量少于 3，返回全部有效笔记。

## 22. 本地应用数据存储详细设计

### 22.1 存储结构（Obsidian 风格 .md 文件）

每个笔记保存为独立的 `.md` 文件，元数据存储在 YAML frontmatter 中。

Vault 目录结构：

```text
{userData}/personal-knowledge-notes/vault/
  .vault-meta.json          # 文件夹元数据 { version: 2, folders: [...] }
  notes/                    # 根目录笔记（folderId === null）
    React_Hooks_学习笔记.md
  folders/                  # 按文件夹 UUID 分目录
    <folder-uuid>/
      笔记标题.md
```

.md 文件格式：

```yaml
---
id: “a1b2c3d4-e5f6-7890-abcd-ef1234567890”
title: “React Hooks 学习笔记”
tags:
  - “React”
  - “前端”
folderId: null
sourceType: “manual”
createdAt: “2026-05-01T10:00:00.000Z”
updatedAt: “2026-05-01T10:30:00.000Z”
lastOpenedAt: null
lastReviewedAt: null
---
# useState

useState 用于在函数组件中管理状态。
```

说明：

- `{userData}` 必须由 Electron 主进程通过 `app.getPath('userData')` 获取。
- 不要把用户数据写入项目源码目录。
- 文件夹目录使用 UUID 命名，重命名文件夹只更新 `.vault-meta.json`，不移动文件。
- 笔记文件名基于标题生成（中文保留，特殊字符替换为 `_`），同名文件通过 ID 后缀区分。
- 写入采用原子操作：先写 `.tmp` 临时文件，再 `rename` 覆盖目标文件。

### 22.2 读取流程

```text
应用启动
↓
主进程扫描 vault 目录
↓
如果 vault 为空且存在旧 notes.json → 自动迁移
如果 vault 为空且无旧数据 → 返回空数组
↓
读取 .vault-meta.json 获取文件夹列表
↓
扫描 notes/ 和 folders/ 目录下所有 .md 文件
↓
解析每个文件的 YAML frontmatter 重建 Note 对象
↓
通过 IPC 返回 { notes, folders }
```

异常处理：

- 单个文件解析失败：跳过该文件，记录警告，不中断整体加载。
- `.vault-meta.json` 缺失或损坏：返回空文件夹列表。
- YAML frontmatter 缺失字段：使用默认值兜底。

### 22.3 写入流程

```text
notes 变化
↓
渲染进程调用 preload API
↓
preload 通过 IPC 通知主进程
↓
主进程对比 fileIndex 差量：
  - 新笔记 → 创建 .md 文件
  - 内容变更 → 原子重写 .md 文件
  - 标题/文件夹变更 → 删除旧文件 + 创建新文件
  - 删除的笔记 → 移除 .md 文件 + 清理空目录
↓
更新 .vault-meta.json
↓
刷新 fileIndex
↓
更新保存状态
```

异常处理：

- 文件系统不可写：展示错误提示。
- 单个文件写入失败：记录错误，继续处理其他文件。
- 磁盘空间不足：展示”保存失败，本地磁盘空间可能不足”。
- 写入失败时不要清空内存中的 notes。

### 22.4 IPC API 设计

IPC 接口保持不变，渲染层无感知：

```ts
type NotesDesktopApi = {
  loadNotes: () => Promise<{ notes: Note[]; folders: Folder[] }>;
  saveNotes: (notes: Note[], folders?: Folder[]) => Promise<{ success: boolean; error?: string }>;
  getStorageInfo: () => Promise<{ path: string }>;
};
```

暴露方式：

```ts
contextBridge.exposeInMainWorld('notesApi', {
  loadNotes,
  saveNotes,
  getStorageInfo
});
```

安全要求：

- `contextIsolation` 必须开启。
- `nodeIntegration` 必须关闭。
- IPC channel 使用固定名称，不允许渲染进程传入任意文件路径。
- 主进程只读写 Vault 目录下的 `.md` 文件和 `.vault-meta.json`。

## 29. Obsidian 风格能力规格

### 29.1 Vault 本地笔记库

用户概念：

- Vault 是一个本地知识库。
- 一个 Vault 中包含多个 Markdown 笔记。
- MVP 可以先只支持一个默认 Vault。
- 后续可以扩展为多 Vault。

实现要求：

- 应用首次启动时自动创建默认 Vault。
- Vault 元数据保存在应用数据目录。
- 笔记内容可以继续存入 `notes.json`，也可以存成独立 `.md` 文件。
- 如果选择 `.md` 文件模式，需要另存一个索引文件保存标签、时间、复习状态等元数据。

MVP 推荐：

- 继续使用 JSON 文件作为主存储，降低实现复杂度。
- 在数据模型中预留 `path`、`folderId`、`links`、`backlinks` 字段。
- 后续再迁移到真实 Markdown 文件夹。

### 29.2 文件树 / 文件夹视图

界面位置：

- 左侧栏顶部显示文件树。
- 文件树下方显示标签、今日回顾和最近编辑。

基础能力：

- 展示文件夹。
- 展示文件夹下的笔记。
- 支持新建文件夹。
- 支持重命名文件夹。
- 支持把笔记移动到文件夹。
- 未归类笔记显示在“未归档”分组。

MVP 可简化：

- 文件夹可以只是一层结构。
- 暂不要求拖拽移动，可以用下拉菜单或选择器移动。

### 29.3 双链语法

支持语法：

```md
[[笔记标题]]
[[笔记标题|显示文本]]
```

解析规则：

- 在 Markdown 正文中识别 `[[...]]`。
- 如果链接目标标题存在，渲染为可点击内部链接。
- 如果链接目标不存在，渲染为“待创建链接”状态。
- 点击已存在链接，打开对应笔记。
- 点击不存在链接，创建同名新笔记并建立链接关系。

示例：

```md
今天学习了 [[React Hooks]]，其中 [[useState|状态管理]] 是最基础的部分。
```

验收标准：

- 输入 `[[React Hooks]]` 后，预览区能显示为内部链接。
- 点击内部链接能打开目标笔记。
- 点击不存在的内部链接能创建新笔记。

### 29.4 反向链接

定义：

- 当前笔记 A 被其他笔记引用时，这些引用来源就是 A 的反向链接。

界面位置：

- 编辑器右侧或底部显示“反向链接”面板。

展示内容：

- 来源笔记标题。
- 命中的上下文片段。
- 点击后打开来源笔记。

规则：

- 反向链接由所有笔记内容中的 `[[当前笔记标题]]` 计算得到。
- 不建议把反向链接持久化为唯一真相，可以作为派生数据实时计算。
- 当标题变更时，需要重新计算链接关系。

### 29.5 出链

定义：

- 当前笔记正文里主动引用的其他笔记，称为出链。

展示内容：

- 当前笔记链接到哪些笔记。
- 哪些链接尚未创建目标笔记。

用途：

- 帮助用户整理知识网络。
- 引导用户补全未创建笔记。

### 29.6 知识图谱

MVP 图谱要求：

- 每篇笔记是一个节点。
- `[[双链]]` 是节点之间的边。
- 当前选中笔记节点高亮。
- 点击节点打开对应笔记。
- 支持全局图谱和当前笔记局部图谱。

推荐实现：

- 可以使用 SVG、Canvas 或成熟图谱库。
- MVP 可以先使用 SVG force layout 或简单圆形布局。
- 如果不引入复杂图谱库，至少要能展示节点和连线。

图谱筛选：

- 按标签筛选。
- 只看当前笔记的一跳关系。
- 隐藏孤立节点。

验收标准：

- 创建两篇互相链接的笔记后，图谱中出现两个节点和一条边。
- 点击图谱节点能打开笔记。
- 当前笔记节点有明显高亮。

### 29.7 命令面板

触发方式：

```text
Ctrl + K
```

Mac 可支持：

```text
Cmd + K
```

命令列表：

- 新建笔记
- 快速打开笔记
- 搜索全部笔记
- 插入内部链接
- 打开知识图谱
- 打开今日回顾
- 随机复习
- 切换编辑 / 预览
- 导出当前笔记

交互要求：

- 打开命令面板后输入关键词可以过滤命令。
- 支持键盘上下选择。
- 支持 Enter 执行。
- 支持 Esc 关闭。

### 29.8 快速切换

触发方式：

```text
Ctrl + P
```

能力：

- 输入关键词搜索笔记标题。
- 支持键盘选择。
- Enter 打开笔记。

体验要求：

- 比完整搜索更轻。
- 主要用于快速跳转，而不是展示详细结果。

- 笔记数据、文件夹、标签、链接关系、回顾状态保存在本机。
- 默认存储路径使用 Electron 的 `app.getPath('userData')`。
- 渲染进程不能直接访问 Node `fs`。
- 本地数据读写必须由 Electron 主进程处理。
- preload 只暴露明确的安全 API。

当前推荐数据路径：

```text
<系统应用数据目录>/personal-knowledge-notes/notes.json
```

后续如果迁移为 Markdown 文件夹模式，推荐结构：

```text
<用户选择的 Vault 目录>/
  notes/
    xxx.md
  attachments/
  .knowledge-vault/
    index.json
    metadata.json
```

MVP 阶段可以继续使用 `notes.json`，但 UI 和文档中需要保留 Vault 概念。

### 39.3 禁止引入的默认能力

除非用户主动启用分享功能，否则不要实现或默认开启：

- 自动云同步
- 自动上传
- 远程数据库
- 用户账号系统
- 在线协作编辑
- 默认联网 AI
- 后台遥测
- 自动收集使用数据
- 自动发送日志

如果未来需要 AI，必须是可选增强：

- 未配置 AI 时，所有基础笔记能力仍可用。
- AI 配置不能阻塞本地知识库使用。
- AI 请求前必须明确让用户知道会发送哪些内容。

### 39.4 联网分享的产品边界

知识库可以通过联网分享，但分享必须是“显式、可控、可撤销或可替换”的能力。

允许的分享方式按优先级排序：

1. 导出为静态 HTML 包。
2. 导出为 Markdown 压缩包。
3. 生成只读分享包，由用户自行发送。
4. 局域网临时只读分享。
5. 可选远程发布，只发布用户选择的笔记或文件夹。

不允许的默认行为：

- 自动把整个 Vault 上传到云端。
- 后台自动同步所有笔记。
- 未确认就分享附件。
- 未确认就分享隐藏元数据。
- 分享本地绝对路径。
- 分享系统用户名、设备路径、应用日志。

### 39.5 分享功能 MVP 方案

第一阶段不要直接做复杂云服务，先做本地导出型分享。

#### 方案 A：导出 Markdown 分享包

用户流程：

```text
选择笔记 / 文件夹 / 整个 Vault
-> 点击“导出”
-> 选择 Markdown 压缩包
-> 应用生成 zip
-> 用户自行发送给别人
```

导出内容：

- `.md` 文件
- 附件
- `metadata.json`
- `README.md`

验收：

- 可以只导出选中的笔记。
- 可以导出整个知识库。
- 导出的 Markdown 能被其他 Markdown 工具打开。
- 不包含本机绝对路径。

#### 方案 B：导出静态 HTML 分享包

用户流程：

```text
选择笔记 / 文件夹 / 整个 Vault
-> 点击“导出”
-> 选择静态网页
-> 应用生成 html/css/js 静态目录
-> 用户可压缩发送或自行托管
```

功能要求：

- Markdown 渲染为 HTML。
- 双链变成站内链接。
- 标签可展示。
- 附件可访问。
- 搜索可以先不做，或做纯前端本地索引。

验收：

- 打开 `index.html` 可浏览导出的知识库。
- 不需要服务器也能基本查看。
- 双链跳转有效。
- 不包含未选择的笔记。

#### 方案 C：局域网临时分享

用户流程：

```text
选择分享范围
-> 点击“局域网分享”
-> 应用启动本机只读 HTTP 服务
-> 显示局域网访问地址
-> 用户点击停止分享后服务关闭
```

安全要求：

- 默认不开启。
- 每次分享都需要用户主动启动。
- 只读。
- 显示当前分享范围。
- 显示访问地址。
- 提供“停止分享”按钮。
- 应用关闭时自动停止分享。

验收：

- 同一局域网设备可以访问分享地址。
- 只能看到用户选择的笔记范围。
- 停止分享后地址不可访问。

#### 方案 D：远程发布

远程发布作为后续增强，不作为第一阶段默认目标。

可选实现：

- 发布为静态站点。
- 用户自己选择部署位置。
- 支持导出到本地目录后，由用户手动上传。
- 如果未来内置发布功能，必须在上传前展示待上传内容清单。

### 39.6 分享前确认规则

任何联网分享前，应用必须展示确认信息：

## 41. 产品体验原则：像 ima 一样简单，面向小白用户，操作丝滑流畅

本节新增体验方向：应用虽然具备 Obsidian 风格的本地知识库能力，但不能做得复杂难懂。操作逻辑要像 ima 这类轻量知识工具一样简单直接，小白用户第一次打开也能自然上手。

### 41.1 核心体验目标

最终体验应满足：

- 第一次打开就知道从哪里开始。
- 不需要学习复杂概念也能记笔记。
- 不需要理解“双链”“Vault”“图谱”才能使用基础功能。
- 创建、编辑、搜索、速记、导出都应该是直觉操作。
- 高级能力隐藏在合适位置，不干扰基础写作。
- 所有操作反馈及时、平滑、不卡顿。
- 应用整体感觉轻、快、稳。

一句话目标：

```text
新手像用普通笔记一样轻松开始，熟练后自然发现双链、图谱、导出等知识库能力。
```

### 41.2 面向小白用户的交互原则

必须遵守：

- 首页不能空洞，空状态要告诉用户下一步做什么。
- “新建笔记”“速记”“搜索”必须始终容易找到。
- 不用术语吓人，优先使用用户能理解的词。
- 复杂功能要有自然入口，不要堆满按钮。
- 默认设置应该已经够好，不要求用户先配置。
- 删除、导出、分享这类高影响操作需要清晰确认。
- 错误提示要说人话，告诉用户怎么恢复。

推荐文案：

```text
还没有笔记，创建第一篇开始记录。
没有找到结果，试试换个关键词。
已保存。
保存失败，请稍后重试。
导出前请确认要分享的内容。
```

避免文案：

```text
Vault 初始化失败。
Graph node missing。
IPC error。
Serialize failed。
```

内部可以使用技术概念，界面上要转换成人能懂的表达。

### 41.3 像 ima 一样简单的操作路径

小白用户最短路径必须非常短。

#### 路径 1：快速记录

```text
打开应用
-> 点击“新建笔记”
-> 输入内容
-> 自动保存
```

验收：

- 3 秒内能找到“新建笔记”。
- 输入后不需要手动保存。
- 保存状态清晰可见。

#### 路径 2：快速速记

```text
打开应用
-> 点击“速记”
-> 粘贴一段内容
-> 点击“保存为笔记”
```

验收：

- 不需要配置 AI。
- 不需要选择复杂参数。
- 默认模板就能生成可读 Markdown。

#### 路径 3：快速找回

```text
打开应用
-> 点击搜索框
-> 输入关键词
-> 点击结果
```

验收：

- 搜索框始终明显。
- 搜索结果即时更新。
- 搜索标题、正文、标签都有效。

#### 路径 4：轻量整理

```text
打开笔记
-> 输入标签
-> 或拖入文件夹
```

验收：

- 标签输入简单。
- 文件夹拖拽有明显反馈。
- 不要求用户先设计复杂分类体系。

### 41.4 高级能力的渐进呈现

应用支持双链、图谱、反向链接，但这些不应该压迫新手。

默认优先级：

1. 新建笔记
2. 搜索
3. 速记
4. 最近编辑
5. 标签
6. 文件夹
7. 双链
8. 反向链接
9. 图谱
10. 导出 / 分享

交互原则：

- 基础功能永远显眼。
- 高级功能放在侧栏、右栏或命令面板。
- 图谱不是首屏主角。
- 分享/导出是工具能力，不要喧宾夺主。
- 命令面板帮助熟练用户提速，但不是小白必经入口。

### 41.5 丝滑流畅的操作要求

应用必须给用户“手跟得上脑子”的感觉。

性能目标：

- 应用启动后主界面尽快可交互。
- 输入标题和正文时不能卡顿。
- 搜索输入时反馈即时。
- 切换笔记要顺滑。
- 打开命令面板和快速切换要迅速。
- 速记弹窗打开要迅速。
- 文件夹拖拽不能明显掉帧。
- 图谱打开可以稍慢，但需要有加载状态。

建议指标：

```text
普通笔记输入延迟：感知上接近即时
搜索反馈：100ms - 200ms 内更新
命令面板打开：100ms 内
快速切换打开：100ms 内
笔记切换：200ms 内
自动保存状态反馈：立即显示“保存中”，成功后显示“已保存”
```

### 41.6 前端实现建议

Agent 优化流畅度时优先做：

- 搜索结果使用 `useMemo`。
- 最近编辑、标签统计、回顾列表使用派生数据缓存。
- 大列表后续引入虚拟列表。
- 自动保存加入 300ms - 800ms 防抖。
- 避免每次输入都触发昂贵图谱计算。
- 图谱计算只在打开图谱时执行。
- 命令面板和快速切换只在打开时渲染。
- 大附件和图片后续做懒加载。
- 导出和分享走主进程异步执行，渲染层显示进度。
- 长任务不要阻塞输入。

当前 MVP 可先实现：

- 自动保存防抖。
- 搜索防抖或轻量即时搜索。
- 导出中状态提示。
- 图谱打开时显示加载提示。

## 2026-07-17 Phase 3 AI 增强实现纪要

本轮完成 §33.3「第三阶段：AI 增强」的实现。所有 AI 调用经 Electron 主进程转发到 OpenAI 兼容接口；AI 默认关闭，未配置或已禁用时不影响任何本地功能。要点如下：

1. **API Key 配置（AI 设置弹窗）**：头部设置按钮与命令面板「AI 设置」进入；可配置启用开关、baseUrl、模型、API Key；默认 baseUrl `https://api.openai.com/v1`，默认模型 `gpt-4o-mini`；支持连接测试（返回延迟毫秒数）与一键清除 Key。
2. **AI 文本整理**：速记支持 5 种整理方式（学习笔记 / 会议纪要 / 项目笔记 / 提取行动项 / 提取知识点），走 OpenAI 兼容 chat completions；调用失败或未配置时自动回退本地模板整理。
3. **AI 摘要**：编辑器内一键生成当前笔记摘要，可控制最大长度。
4. **AI 标签推荐**：编辑器内根据标题、正文和已有标签推荐新标签，一键添加。
5. **图片 OCR**：图片速记将选中图片复制进 vault `attachments/`，正文以 `![说明](vault-img://attachments/xxx.png)` 引用并经自定义协议显示；可调用视觉模型 OCR 识别图中文字。
6. **语音转文字**：语音速记使用 MediaRecorder 录音，音频发送至 `whisper-1` 转写，可继续 AI 整理后保存；未配置 AI 时降级为手动粘贴转写文本。

### window.aiApi 契约概览（10 个方法）

- `getConfig()` → `{enabled, baseUrl, model, hasApiKey, maskedApiKey}`（不含明文 Key）
- `saveConfig({enabled, baseUrl, model, apiKey?})`（apiKey 不传 / 空串 = 保持原 Key）
- `clearApiKey()`
- `testConnection()` → `{success, error?, latencyMs?}`
- `organizeText({content, mode, title?})` → `{success, markdown?, error?}`（mode：study / meeting / project / action_items / knowledge）
- `summarize({content, maxLength?})` → `{success, summary?, error?}`
- `suggestTags({title, content, existingTags, max?})` → `{success, tags?, error?}`
- `selectImageToVault()` → `{canceled, relPath?, error?}`（relPath 形如 `attachments/xxx.png`）
- `ocrImage({relPath})` → `{success, text?, error?}`
- `transcribeAudio({data, mimeType, fileName})` → `{success, text?, error?}`

渲染层统一经 `src/api/aiApi.ts` 桥接；非桌面环境调用自动降级。

### 其他实现要点

- **vault-img 自定义协议**：主进程注册 `vault-img://` 协议，将 `vault-img://attachments/xxx.png` 映射到 vault 附件目录，仅用于预览显示；导出时把笔记引用的图片复制进导出包并改写为相对路径。
- **safeStorage Key 加密**：API Key 由主进程用 Electron safeStorage 加密后存本地配置文件，不以明文落盘；渲染层只能看到掩码版本，明文不出主进程。
- **降级策略**：AI 未配置或已禁用时，主进程统一返回 `{ success: false, error: 'AI 未配置或已禁用' }`；速记整理回退本地模板，语音速记回退粘贴文本，摘要 / 标签推荐 / OCR 入口隐藏或提示，本地功能不受影响。
- **语义搜索**：仍为占位（规划中），仅保留入口，后续阶段实现。
- **隐私说明**：开启 AI 后，笔记 / 速记内容会发送至所配置的 API 服务，隐私政策以该服务商为准；默认关闭。
